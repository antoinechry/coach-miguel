# Coach Miguel — notes pour Claude Code

Application web statique de suivi d'entraînement (calendrier, charge, séances proposées par « Miguel », étude des sorties, bilan hebdo).

## Contraintes
- Tout tient dans `index.html` (pas de build, pas de framework). Interface en français.
- Déploiement : GitHub Pages depuis `main`, racine du dépôt : https://antoinechry.github.io/coach-miguel/
- Backend : projet Supabase `coach-miguel` (réf. `rynbzhuxwvfvblgwnhkk`, `SUPABASE_URL` dans `index.html`). Fonctions edge dans `supabase/functions/` : `coach-propose` (API Claude, secret `ANTHROPIC_API_KEY`), `intervals` (intervals.icu).
- Application distincte de Plan My Ride (dépôt `antoinechry/plan-my-ride`, projet Supabase séparé depuis le 24/10/2026). Coach n'en dépend plus : plus de trace GPX proposée, plus de lien vers Plan My Ride, thème = celui de l'appareil. Mêmes mots de passe qu'avant (auth du projet `coach-miguel`).
- Le plan d'entraînement personnel (`plans/import.json`) n'est pas dans ce dépôt public : il reste dans le projet Claude / la base.
- Les sections ci-dessous (« `coach.html` ») parlent maintenant de `index.html`.

## Coach Miguel (`index.html`) : séances prévues et « Demander une sortie »
- Connexion (`#authbox`) : « Mot de passe » (`signInWithPassword`, « Mot de passe oublié ? » → `resetPasswordForEmail` avec retour sur la page ; l'évènement `PASSWORD_RECOVERY` ouvre le profil pour choisir le nouveau mot de passe). Plus de connexion par lien e-mail (retirée à la demande de l'utilisateur). Bouton « Profil » dans l'en-tête (`#profbtn`) → dialogue `#profdlg` : définir / changer le mot de passe (`updateUser`, 8 caractères minimum), connexion intervals.icu (identifiant athlète, clé API, Synchroniser, Changer de clé ; ancienne section « Activités » du bas de page), déconnexion. Bouton « ↻ Actualiser » dans l'en-tête (`#refbtn`, `refreshAll`, visible une fois connecté, libellé masqué sur mobile) : `intervals` `sync` puis `loadActivities` + `renderCalendar` (charge) + `loadWellness` (santé) ; affiche 4 s « À jour » / « N nouvelles » (activités absentes avant) ou « Échec », détail et heure dans l'infobulle.
- Séances prévues : doc `plan_docs` « seances » (`{ sessions: { 'AAAA-MM-JJ': [ { titre, sport, duree_min, distance_km, denivele_m, intensite, deroule[], pourquoi, source, cree_le } ] } }`), affichées en pointillés dans le calendrier, retirables dans la fenêtre du jour. Ressentis éventuels : doc « ressentis » (`activities[ext_id]`), repris dans la consigne.
- « Demander une sortie » (jours à venir) : la page construit la consigne (`buildPrompt` : profil, forme/fatigue/fraîcheur 42 j / 7 j via `computeSeries`, alertes `computeAlerts`, activités 28 j, séances prévues, dispos, demande) et appelle la fonction edge `coach-propose` (source dans `supabase/functions/coach-propose`, `task` 'propose' ou 'study'), qui interroge l'API Claude avec le secret `ANTHROPIC_API_KEY` (modèle `COACH_MODEL`, défaut `claude-sonnet-5-5`), réservée aux utilisateurs de `COACH_USER_IDS` (défaut : le propriétaire). Réponse JSON validée par `cleanProposal`.
- Envoi des séances prévues vers les appareils (onglet « Sorties prévues », bouton « Envoyer sur ton Dura / ta Garmin », `sendSession`) : action `push_workouts` de la fonction `intervals` → `POST /athlete/{id}/events/bulk?upsert=true` (category WORKOUT, `external_id` = `coach-miguel-<uid>` de la séance, description au format texte d'intervals.icu produite par `icuText`) ; « Retirer » appelle `delete_workouts` (`PUT /events/bulk-delete`). intervals.icu transmet ensuite à COROS (Dura, vélo) et Garmin Connect (montre, course) si « Envoyer les entraînements planifiés depuis Intervals » est coché dans ses connexions, seulement pour les 7 prochains jours (la carte indique la date d'arrivée) ; côté COROS, activer une fois le plan « Intervals.icu Training Plan ». Séance : `uid`, `etapes` (`{ label, min | sec, lo, hi, rampe?, libre?, rpm? }` ou `{ repeter, label, pas[] }`, lo/hi en % de FTP au vélo, en % de FC seuil (LTHR) en course ; sans `etapes`, `defaultEtapes` selon l'intensité), `icu` (`{ id, external_id, envoye_le, charge }`). Profil dessiné par `workoutBars`. Miguel renvoie `etapes` dans ses propositions (`cleanEtapes`).
- Graphique au-dessus du calendrier (`#loadcard`, `renderLoad` appelé par `renderCalendar`) : barres hebdomadaires empilées par sport sur 26 semaines passées + 6 à venir (séances prévues en clair et pointillés), mesure Charge / Temps / Distance (`#lmode`, `localStorage` `cm-load-mode`) ; en mode Charge, courbes quotidiennes forme (42 j) et fatigue (7 j) sur leur propre échelle, pointillées dans le futur ; valeurs du jour + ratio fatigue/forme dans `#lkeys` ; survol = infobulle de la semaine, clic = calendrier sur ce mois ; repliable (`cm-load-open`). Charge prévue d'une séance : celle d'intervals.icu (`icu.charge`) si elle y a été envoyée, sinon durée × `LOAD_PER_H`.
- Proposition de Miguel : boutons « Ajouter et envoyer sur ton Dura / ta Garmin » (ajout + `sendSession`, bascule sur l'onglet Sorties prévues), « Ajouter seulement », « Autre proposition ». Filtres d'intervals.icu : COROS = Cyclisme, VTT, Gravel ; Garmin = Course à pied, Trail.
- Données de santé : action `wellness` de la fonction `intervals` (`/athlete/{id}/wellness`, champs poids, masse grasse, FC au repos, VFC, sommeil, pas, VO2max…), importées par intervals.icu depuis Garmin (balance Index pour le poids : il remonte à chaque nouvelle pesée). Chargées au démarrage sur 120 jours (`loadWellness`, `WELL`). Panneau « Santé » sous le graphique de charge (`#healthcard`, `renderHealth` / `drawHealth`, repliable `cm-health-open`) : « Màj aujourd'hui / hier / 14 oct. » en tête (relevé Garmin le plus récent, `relDay`) et date du dernier relevé dans chaque tuile (depuis le 21/10/2026) ; poids, FC au repos, VFC, sommeil (dernière valeur, moyenne 7 j comparée aux 30 jours précédents, courbe 60 j avec référence en pointillés). `wellPromptLines(date)` ajoute la santé aux consignes de Miguel (proposition : allège si VFC basse, FC au repos +4 bpm ou mauvaise nuit ; étude : santé autour de la sortie).
- Charge d'une activité : `training_load` (intervals.icu), sinon `relative_effort` (Strava), sinon durée × charge horaire du sport (`LOAD_PER_H`).
- Fenêtre du jour (`openDay`) en onglets (`#dlgtabs`, `setTab`, `updateTabs` pour les compteurs) : « Dispo » (dispo + note), « Sorties prévues » (`renderPlans`, message vide + raccourci vers Miguel), « Demander à Miguel » (jours à venir seulement), « Compte rendu » (`renderActs` : une ligne par activité avec ressenti et verdict de l'étude, ouvre la fenêtre de la sortie ; masqué pour un jour futur sans activité). Onglet ouvert par défaut : Compte rendu s'il y a une activité, sinon Sorties prévues s'il y en a, sinon Dispo. « Mon ressenti » (effort 1–10, sensations 1–5, douleur aucune / gêne / douleur + zone, note) est dans la fenêtre de la sortie, enregistré dans le doc « ressentis » (`activities[ext_id]`) et repris par Miguel. Avec un pinceau « Remplir mes dispos » actif, un clic sur une séance prévue ouvre quand même la journée.
- Fenêtre de la sortie (`#actdlg`, `openAct`) : ouverte par un clic sur une activité du calendrier (`.chip[data-act]`, même avec un pinceau actif) ou depuis l'onglet « Compte rendu » de la fenêtre du jour (`renderActs`, boutons `data-open`). Contenu : infos (`actStatsFull` : résumé + `raw` lu à la demande, mis en cache `rawCache`), courbes, zones de puissance et de FC (`renderZones`, réglages intervals.icu de l'activité), ressenti et étude (`feelHTML` dans `#actfeel`).
- Courbes : action `streams` de la fonction `intervals` (`/activity/{id}/streams.json`, moyennes par paquets → 1 500 points max ; seulement pour les activités `source = 'intervals'`, l'ancien cache Strava n'en a pas), cache `streamCache` par session. Dessin canvas maison (`buildCharts` / `drawCharts`) : altitude (aire), vitesse (ou allure inversée en course), FC, puissance (échelle au 99,5e centile), cadence (moyenne hors zéros) ; axe distance ou temps (`#xmode`) ; curseur commun au survol ou au doigt (`hoverAt`, `#actread`) ; couleurs `--c-alt/-spd/-hr/-pw/-cad` (thème clair et sombre).
- « Étude de la sortie par Miguel » (bouton sous le ressenti, dans la fenêtre de la sortie) : `buildStudyPrompt` lit `raw` de l'activité à la demande (zones de puissance et de FC d'intervals.icu avec leurs réglages, IF, VI, EF, découplage, eFTP, efforts détectés, glucides, échauffement, météo) + ressenti, séance prévue ce jour-là, forme la veille et après, FC max observées sur 12 mois, sorties comparables (même sport, 5 mois, durée ×0,6–1,6), 7 jours précédents, séances des 5 jours suivants ; fonction `coach-propose` avec `task: 'study'`. Résultat validé par `cleanStudy`, gardé dans le doc « etudes » (`activities[ext_id]` ; la contrainte `plan_docs_doc_check` liste les docs autorisés : dispos, seances, ressentis, etudes) : rouvrir la journée ne rappelle pas l'API (« Refaire l'étude » pour relancer). `callCoach` traduit les erreurs (dont « crédit épuisé » et réponse coupée). Fonction : `max_tokens` 2500 (propose) / 4000 (study), `parseJson` tolérant (bloc de code, texte autour, virgules finales) ; en cas d'échec elle renvoie `stop`, `head`, `tail` pour diagnostiquer.
- Rapatriement (21/10/2026) : l'action `sync` de la fonction `intervals` renvoie `missing` (activités qu'intervals.icu a reçues de Strava et ne donne pas : date, type, source, distance). `renderMissing` les affiche dans le profil sous « Synchroniser » (et après « Actualiser ») : nombre, celles absentes du calendrier (pas dans l'ancien cache Strava), marche à suivre (intervals.icu → Connections → Garmin Connect / COROS : import des activités + « Download old data »). Constat du 21/10/2026 : intervals.icu ne donne que les sorties COROS Dura depuis le 19/09 ; les courses (Garmin fēnix 7) n'arrivent que via Strava, donc bloquées.

## Vue Outils et pression des pneus (04/11/2026)

- Carte `#tirecard` (déplacée d'Aujourd'hui vers Outils) : pression avant / arrière en bars et psi ; lignes « Vélo » (si plusieurs) et « Montage » (pastilles `.tchip` des montages enregistrés, celle qui correspond au vélo est cochée ; « + Enregistrer ce montage » sinon, avec le résumé du montage actuel), surface (Route, Chemins blancs, Gravel cassant) ; « Régler › » ouvre `#tireform` en 3 blocs (Le vélo / Montage des pneus / Toi et la météo) + liste « Mes montages enregistrés » (Supprimer).
- Montages : `MONT_KEYS` = largeur, jante, type, carcasse, hookless, max. « Enregistrer ce montage » ouvre `#tmform` (nom proposé « 28 mm chambre à air », un nom déjà pris remplace l'ancien) ; clic sur une pastille = copie du montage dans le vélo choisi. Correspondance par `sameMont` (valeurs normalisées par `montOf`), pas d'identifiant stocké dans le vélo.
- Calcul `gpPressure` : algorithme du simulateur de Gravel Passion (gravelpassion.fr/calculateur-pression-pneu-velo, script relevé le 04/11/2026) recopié à l'identique : table `GP_TABLE` (largeur mesurée 25–60 mm × poids total 50/60/85/110/130 kg, interpolation linéaire), coefficients `GP_COEF` (type de pneu, surface en bar soustraits, carcasse, priorité, répartition de charge), correction de poids, coefficient de jante (idéal = largeur × 0,55 borné 17–27 mm), humide × 0,96, arrière + 5,5 à 11,5 % selon largeur et poids, minimum anti-pincement par type et largeur, plafond hookless indicatif et limite max saisie. Vérifié sur 5 cas : mêmes valeurs que leur page.
- Réglages : doc « reglages », clé `pneus` = `{ cur, pilote, meteo: 'auto'|'sec'|'humide', velos: [ { id, nom, velo (kg chargé), largeur, jante, type, carcasse, priorite, charge, surface, hookless, max } ], montages: [ { id, nom, largeur, jante, type, carcasse, hookless, max } ] }` (défaut `TIRE_BIKE_DEF`, un « Vélo de route » 28 mm chambre à air). Enregistrement au fil de la saisie (`saveTires`, 0,7 s).
